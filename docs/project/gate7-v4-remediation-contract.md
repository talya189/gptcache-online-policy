## 1. Prospective status and required disclosure

V4 was designed after the complete v3 matrix and its immutable preterminal
report had been observed. V3 exposed an estimand mismatch: its additive
`500,000 ns` rule compared separate full-request p95 values even though the
full request is dominated by common ONNX embedding work rather than by the
eviction policy. V4 does not hide that fact.

V4 retains a full-request p95 ratio as the user-visible latency guardrail,
moves the inherited additive budget to the complete post-embedding cache path,
and separately bounds request-paired policy-exclusive overhead. The numeric
`500,000 ns` budget is inherited unchanged from the original experiment
contract; it was not selected just above a v3 observation. The metric change
is nevertheless a post-v3 protocol change and must be disclosed as such.

The report, handoff, manifest, and adjudication must use substantially the
following disclosure:

> Gate 7 v4 was designed after v3 completed. V3 remains operationally INVALID
> because it has no TERMINAL ledger event; its immutable preterminal systems
> result is FAIL and its semantic guardrail is FAIL. V3 showed that applying a
> 0.5 ms additive budget to full-request p95 conflates CARMA overhead with
> dominant common ONNX timing variation. V4 therefore retains the full-path
> ratio, applies the inherited absolute-scale budget to post-embedding cache
> latency, and adds a request-paired policy-exclusive overhead guardrail. V4
> uses new seeds and fresh traces. No v1, v2, or v3 result is repaired,
> reclassified, or reused as v4 confirmatory evidence.

Any retrospective application of the v4 metrics to v3 is descriptive design
evidence only. It cannot establish a v3 or v4 PASS.

## 3. Gate 2 and semantic quality remain separate

Gate 2 used calibration-only threshold selection with grid
`0.80, 0.81, ..., 0.99`. It selected the lowest threshold whose one-sided 95%
Wilson precision lower bound was at least `0.99`. No threshold qualified on
7,729 calibration pairs, so the threshold stayed null and the 56,963 held-out
rows were not evaluated beyond reading their split field.

Gate 2 therefore remains **FAIL / no qualifying threshold**. The v4 systems
run retains `0.97` only as the previously specified controlled operating point.
It is not a Gate 2-qualified semantic threshold.

Every raw cache hit is independently classified as same-component,
direct-negative, component-derived-negative, unlabeled cross-component, or
unresolved. The semantic guardrail is reported separately:

- `FAIL` if any labeled-negative hit occurs;
- `PENDING_INDETERMINATE` if there are no labeled-negative hits but at least one
  unlabeled cross-component hit;
- `PASS_OBSERVED` if every raw hit is same-component;
- `NO_HITS` if no raw hit occurs.

Semantic observations do not abort the matrix and do not alter the v4 systems
status. A v4 systems PASS may coexist with semantic FAIL, and both must be
shown. Neither can reverse the Gate 2 result.

## 8. Full-path and stage timing

`time.perf_counter_ns()` is the monotonic timer. The request timer starts
immediately before real prompt text enters the measured adapter path and ends
immediately after `gptcache.adapter.adapter.adapt` returns the materialized
response.

Mutually exclusive timing fields are:

- `text_preprocess_tokenize_ns`;
- `onnx_inference_ns`;
- `embedding_postprocess_ns`;
- `faiss_search_ns`;
- `sqlite_read_ns`;
- `similarity_decision_ns`;
- `policy_exclusive_ns`;
- `sqlite_write_ns`;
- `faiss_mutation_ns`;
- `response_return_ns`;
- `residual_ns`.

Nested SQLite/FAISS calls are charged to their storage stages, not to
`policy_exclusive_ns`. LRU, LFU, and CARMA use the same instrumentation
boundaries. Every request must satisfy exact integer identities:

```text
embedding_ns = text_preprocess_tokenize_ns
             + onnx_inference_ns
             + embedding_postprocess_ns

post_embedding_total_ns = request_total_ns - embedding_ns

cache_management_ns = policy_exclusive_ns
                    + sqlite_write_ns
                    + faiss_mutation_ns

request_total_ns = sum(all mutually exclusive stages, including residual_ns)

end_to_end_ns = request_total_ns
post_embedding_ns = post_embedding_total_ns
```

Negative, missing, nonfinite, or unreconciled timing is structural invalidity.
`embedding_elapsed_ns`, `policy_inclusive_ns`, and
`post_embedding_elapsed_ns` are overlapping diagnostics and are excluded from
the mutually exclusive sum.

For a sample list of size `N`, p50/p95/p99 use nearest rank
`ceil(q*N)`. Quantiles are computed from raw values; stage quantiles are never
added or subtracted. Service throughput is
`N / (sum(request_total_ns) / 1e9)`. Rounded CSV fields and loop-duration
diagnostics never adjudicate the gate.

For the policy-exclusive paired guardrail, CARMA and LRU rows are matched by
seed, exact trace hash, exact request ID, and request index. For each matched
request `i`:

```text
policy_delta_i = CARMA.policy_exclusive_ns_i
               - LRU.policy_exclusive_ns_i
```

The guardrail input is nearest-rank `p95(policy_delta_i)`, not the difference
between the two separate policy p95 values. Missing, duplicate, or inconsistent
pair keys are structural invalidity.

The old v1-v3 quantity
`p95(CARMA request_total_ns) - p95(LRU request_total_ns)` remains mandatory as
a legacy diagnostic. It does not determine v4 PASS or FAIL.

## 9. Request, CPU, and memory evidence

The child preallocates and physically touches fixed-capacity request and
embedding-evidence buffers before the resource baseline. It performs no
per-request disk logging or in-process resource sampling while request timers
are active. After measurement it serializes all 45,000 request rows.

Each row contains trace/request identity, input provenance, hit/miss and
candidate evidence, returned response identity, semantic classification,
policy action, admission/rejection/eviction, cache sizes, stale/capacity/
structural flags, and every timing field.

The parent samples each child externally from ready acknowledgement through
measured-loop completion. Start, end, and periodic samples record monotonic
start/completion time, collection duration, RSS, VMS, USS when supported,
user/system CPU, thread count, and process I/O when supported. Unsupported
fields are null with availability metadata. Sampling is synchronous and uses
absolute deadlines. A periodic start-to-start gap greater than `200,000,000 ns`
invalidates that run. Formal peak RSS is the maximum sampled RSS inside the
formal window; lifetime high-water RSS is diagnostic only.

## 10. Frozen six-check v4 systems adjudication

For each seed, pair CARMA and LRU by exact trace hash. All six conditions must
hold for every seed:

```text
1. p95(CARMA request_total_ns) / p95(LRU request_total_ns) <= 1.25

2. p95(CARMA post_embedding_total_ns)
   - p95(LRU post_embedding_total_ns) <= 500,000 ns

3. p95 over request-paired
   (CARMA policy_exclusive_ns - LRU policy_exclusive_ns) <= 500,000 ns

4. CARMA service_throughput_qps / LRU service_throughput_qps >= 0.90

5. CARMA peak RSS / LRU peak RSS <= 1.20

6. CARMA peak RSS - LRU peak RSS <= 67,108,864 bytes
```

The two latency differences are directional `CARMA - LRU` differences, not
absolute-value operations. A negative difference passes. All values are
computed from unrounded raw evidence. The post-embedding check compares the
two separately recomputed marginal p95 values. The policy-exclusive check uses
the p95 of request-paired differences defined in Section 8.

The systems result is:

- **PASS**: all 15 children are structurally valid, the complete evidence is
  independently reproducible, and all 30 seed-check booleans are true;
- **FAIL**: the matrix is complete and structurally valid, but at least one of
  the 30 numerical booleans is false;
- **PENDING**: a developmental or smoke bundle is intentionally incomplete and
  therefore cannot make a formal numerical claim;
- **INVALID**: formal evidence is structurally unusable because of provenance,
  process, provider, configuration, timing, storage, artifact, ledger, source,
  or execution failure.

A formal child/process failure is INVALID, not a favorable PENDING result.
There is no averaging, majority vote, pooled-request quantile, favorable-seed
removal, selective rerun, post-result bound change, or bootstrap override.

LFU results, p50/p99 values, cache-management time, policy-inclusive time,
incremental memory, CPU, I/O, and across-seed summaries are mandatory
diagnostics. Gate 2 and semantic status remain separately reported.

Gate 7 is an overhead non-inferiority result. It must not be presented as the
project's statistically significant performance gain; that claim requires the
separately preregistered workload result and its paired statistics.

```json
{"path":"docs/project/gate7-v4-remediation-contract.md","sha256":"<frozen-sha256>","bytes":<frozen-byte-count>}
```

The preterminal report content-addresses the manifest; the terminal intent
content-addresses both report and manifest; and TERMINAL content-addresses

duplicating a differently shaped contract object.

Every standalone source, auditor, report, contract, manifest, or terminal

`{path, sha256, bytes}`. If such a map is keyed by path, the nested `path`

ignored, or continued in place.

structurally valid complete v4 attempt is the only eligible numerical result.

The ordinary offline auditor runs only after a completed TERMINAL permits it.
It writes `gate7-adjudication.json` without altering manifest, preterminal
report, ledger, or raw evidence.

## 17. Interpretation limits

V4 is a fixed-host, same-machine policy comparison with pinned application and
Python dependency bytes. It is not a complete hermetic machine image: kernel,
hardware, system libraries, filesystem implementation, and every OS scheduling
decision are observed or constrained but not all content-pinned.

A v4 PASS supports only the six frozen systems non-inferiority statements on
these five new QQP-derived traces. It is not a population semantic-precision
claim, does not repair Gate 2, does not erase the semantic guardrail, does not
reclassify v1-v3, and does not by itself establish CARMA's separate hit-rate
performance-gain claim.
